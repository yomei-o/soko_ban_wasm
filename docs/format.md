# 倉庫番 Select 30 (PC-98) — データ形式

Thinking Rabbit, 1990年代前半、MEG-DOS 起動の 2HD フロッピー 1 枚。
すべて実物 `orig/倉庫番Select30.fdi` (1265664 バイト) から読み出したもの。

## ディスク

FAT12、1024 バイト／セクタ、77 シリンダ × 2 ヘッド × 8 セクタ。
FDI ヘッダは 4096 バイト。`python tools/fat12.py <image> disk` で 41 ファイル。

| ファイル | 大きさ | 役 |
|---|---|---|
| `SBP98.EXE` | 129375 | 本体。MZ、ラージモデル |
| `SBPMEN.DAT` | 7798 | **30 面の盤面**（下記） |
| `SBPUSER.DAT` | 310 | ユーザ面。出荷時は全 0 |
| `TRACE.DAT` | 112000 | 手順の記録。出荷時は全 0 |
| `SBPWAIT.DAT` | 18 | `211:211:422:408` — 機種別の待ち値 |
| `SBPVOICE.VOI` | | 声 |
| `SBPBGM0`..`5.BGM` | | 曲 6 本 |
| `CHR98N.CG` / `.CGM` | | タイル絵と、そのマスク |
| `TITLE`, `SELECT`, `CLEAR`, `PEKE`, `END1`, `END2`, `STAFF1/3/4`, `LOGO`, `WINDOWS`, `FONT` | | 各画面の絵。`.CG` が絵、`.CGM` / `M.CG` がマスク |
| `IO98.SYS`, `MEGDOS.SYS`, `MMD2.SYS`, `MOUSE.SYS` | | MEG-DOS 一式 |

`SBP98.ADD` が音源ドライバ MMD2 とマウスを読む。`SOKO.BAT` が起動。

## SBPMEN.DAT — 30 面の盤面

7798 バイトのうち非ゼロは 869 バイトしかない。床がビット 0 のビットマップだから。

非ゼロの位置がきれいに **250 バイト周期**で、1 周期の中では +0x0e, +0x5a,
+0xb2 に固まる。これは +0x0a の配列の 4 バイト目、+0x5a の配列の頭、+0xaa の
配列の 8 バイト目。20 語 × 4 バイト = 80 バイトの配列 3 本と 10 バイトの
ヘッダで、ちょうど 250 になる。

```
+0x00  1   タイルの大きさ。3 か 2。広い 7 面だけが 2
+0x01  1   自機の開始桁
+0x02  1   自機の開始行
+0x03  2   目標手数、16bit LE（面 1 = 71、面 26 = 2001）
+0x05  5   0
+0x0a  80  ゴール   20 行 × 32 ビット
+0x5a  80  壁
+0xaa  80  箱
```

どのプレーンが何かは `FUN_1edb_338f`（原作の読み込み）で確定する:

```
コード = 4*plane0 + 2*plane1 + 1*plane2
マス   = DS:0xba[コード]        表は 00 02 01 09 03 04 09 09

  コード 0  何も無し      -> 0  床
  コード 1  plane2 だけ   -> 2  そして FUN_1edb_2bb9 が値 2 を
                                0x1d..0x2b の 15 種に差し替える
                                = 花王の製品パッケージ。**plane2 が箱**
  コード 2  plane1 だけ   -> 1  壁
  コード 4  plane0 だけ   -> 3  青い点が出る。**plane0 がゴール**
  コード 5  plane0+plane2 -> 4  ゴールの上の箱
  コード 3, 6, 7          -> 9  ありえないので詰め物
```

最初は箱とゴールを逆に読んでいた。数が等しく、どちらで読んでも成立する
パズルになるので盤を眺めても分からない。**「パッケージで描かれる方が箱」**
という絵の側からしか決まらない。

### 表示寸法 — `FUN_1edb_31c5`

```
DS:0x00a0  20 24 32 40      タイルの画素数
DS:0x00a8  31 25 19 15      格子の幅（最終添字なので +1 がマス数）
DS:0x00b0  19 15 11  9      格子の高さ
```

640/20 = 32、400/20 = 20 …と、画面をタイルで割った値。原作は添字 3 から
下げて**最初に収まった大きさ**を採り、盤をその格子の中央にマス単位で寄せる:

```
size   = 3 から下げて (w-1 <= 幅表[i] && h-1 <= 高表[i]) の最初
shiftX = (幅表[size] - (w-1)) / 2
shiftY = (高表[size] - (h-1)) / 2
原点   = (shiftX * タイル, shiftY * タイル)
```

30 面すべてで `size` が面ヘッダの先頭バイトと一致するので、あのバイトは
**表示寸法の添字**で確定。画素単位で中央寄せすると奇数の盤で半タイルずれる。

**行の並びは MSB 先頭** — 先頭バイトのビット 7 が桁 0。PC-98 の VRAM と同じ
向きで、タイルのビットマップと揃っている。逆向きに読んでも壁の上には何も
乗らないが（盤がほぼ左右対称なので）、非対称な面が鏡像になり自機が床から
外れるので判別できる。

レコード 0 は全ゼロ、**レコード 1〜30 が 30 面**、末尾に 48 バイトの余り。

30 面すべてで次が成り立つ（`tools/men.py` が検定する）:

* 箱の数 == ゴールの数
* 箱もゴールも壁の上に無い
* 自機は床の上から始まる

```
python tools/men.py disk/SBPMEN.DAT        30 面を絵にする
python tools/men.py disk/SBPMEN.DAT 11     1 面だけ
python tools/men.py disk/SBPMEN.DAT --c    C の表にする
```

## SBP98.EXE

MZ、ヘッダ 4608 バイト、本体 124767 バイト（`tmp/SBP98.BIN`）。
再配置 1103 個（0x0022 から）、CS:IP = 0000:0000、SS:SP = 1e17:00e6。

再配置の分布から、大きなセグメントが 2 つ

* `0x0000` — 修正 150 個、参照 289 回
* `0x0edb` — 修正 486 個、参照 153 回

に、小さなものが 60 ほど `0x1ae2` まで並ぶ。ラージモデルの C。
`"Font file not found ("`、`"Invalid graphics mode for selected driver"` は
Borland BGI の文言なので Turbo C / Borland C++。

**DS = 0x19ca**（本体の 105632 = 0x19ca0 バイト目）、そこから終端まで 19135
バイト。初期化済みは DS:0x4aa0 まで。DS:0x036e からファイル名の表:
`sbpmen.dat`, `usermen.dat`, `trace.dat`, `sbpuser.dat`, `sbpwait.dat`,
`LOGO.CG`, `sbpvoice.voi`, `sbpbgm0`..`5.bgm`, `windows`, `chr98n`, `font.cg`,
`select`, `clearm`, `staff1/3/4`。DS:0x03a5 から日本語の文言:

```
でした、今回の手順を保存しますか？
　【ＤＩＳＫを入れてください】
　【ＤＩＳＫに書き込めません】
実行するためのメモリが足りません。６４０ＫＢに増設してください。
フォーマット中画面にノイズが出ます
```

DS:0x0dee に 18 語の表があり、いずれも DS:0x0eaf 以降を指す（間隔 1,4,5,4,
6,8,8,9,7,4）。間隔が小さいので文字列の表。

## .CG / .CGM — 絵

先頭 2 バイトが圧縮長の 16bit LE。`SELECT.CGM` は 9070 バイトで頭が 9068。
これが `大きさ - 2` に合わない 4 本は**無圧縮**:

| ファイル | 大きさ | 中身 |
|---|---|---|
| `WINDOWS.CGM` | 32000 | 640x400 の 1 プレーンそのまま。窓の一覧 |
| `STAFF1.CG` | 64000 | 2 プレーン |
| `LOGO.CG` | 8000 | 1/4 プレーン |
| `FONT.CG` | 3192 | 下記の固定長レコード |

`WINDOWS.CGM` はそのまま描けて、UI の語彙が全部入っている:
EDIT (STAGE / EDIT PLAY / SAVE LOAD / ORIGINAL LOAD / CLEAR BGM / EXIT)、
SELECT (GAME / EDIT / OPTION)、MENU (TRY AGAIN / SELECT STAGE / TRACE / BGM)、
SCORE (STAGE / STEPS / LIMIT)、TRACE (上下の矢印と START)、
TOOL (壁 / 点 / ラビ君 / 荷物 と EXIT)、OPTION の帯、はい・いいえ、数字。

### 走長 — 確定（SBP98.EXE の 2406:09xx を読んだ）

`out/sbp98.asm` の逆アセンブルから、読み込みルーチンはこうなっている:

```
fread(&skip, 1, 2, fp)              先頭の語は読んで捨てる
planes = ([0x90] == 1) ? 4 : 3      2406:0a0d
for p in 0..planes-1:
    dst = seg[p]                    a8000 / b0000 / b8000 / e0000
    di = 0
    while di < 0x7d00:              32000 = 1 プレーン、2406:0aaa
        fread(&c, 1, 1, fp)
        *dst++ = c                  判定の前にまず 1 個書く
        if c == 0x00 || c == 0xff:  2406:0a68 と 2406:0a6e
            fread(&n, 1, 2, fp)
            while n - 1 > si++:     2406:0aa5
                *dst++ = c
            di += n - 1
        di++
```

要点は三つ:

* 走長は「そのバイト自身 + 16 ビットの個数」で、**個数は最初の 1 個を含む**
* **0x00 も 0xff と全く同じに逃げ道になる。** これが抜けていた
* **プレーンごとに 32000 バイトで打ち切る**

マスクは 0 だらけなので流れは `00 NN NN` で埋まっており、その一つ一つで
2 バイトずれていた。だから絵が斜めに崩れていた。プレーンを続けて数えて
いたので大きさも 32000 にわずかに足りなかった。

プレーン数が 3 になる分岐 (`[0x90] != 1`) は 8 色機向けらしい。

これで全部の絵が出る:

* `END1.CG` — 「やったーっ!!」の絵。ラビ君と 倉庫番 Select 30 の木箱
* `TITLE.CG` — 楕円の銘板に 倉庫番 / Soko-ban / Select 30 /
  SINCE 1982 / (C) THINKING RABBIT INC.
* `CHR98N.CG` — **タイル一式**。壁（煉瓦）、ゴール印、点、木箱、
  ラビ君の歩行 4 方向を**大小 2 サイズ**で持つ（面ヘッダの `tile` 3 / 2 と対応）。
  荷物は**花王の製品パッケージ**（ソフィナ・アタック・メリット・ビオレ・
  NIVEA ほか）。タイトルの「花王」はこれ

### パレット — 確定

展開器が読むプレーンのセグメント表が **DS:0x0330** にそのまま置いてある:

```
DS:0330  00 a8 00 b0 00 b8 00 e0      = a800 / b000 / b800 / e000
DS:0338  "LOGO.CG"
```

その直前に **16 色 × 3 ニブルのパレットが 3 本**。成分の順は **R G B** で、
各ニブルを 17 倍すると 0..255 になる:

| 置き場 | 用途 | 中身 |
|---|---|---|
| DS:0x02a0 | タイトルの木 | `000 c84 e93 fa4 a73 c84 fa6 fc6 b96 fd9 ff3 0cf f00 f0f 0a0 fff` |
| DS:0x02d0 | タイル | `000 000 940 fdb d32 fb3 dba 01f 0c9 974 096 8f0 651 02a ff0 fff` |
| DS:0x0300 | エンディング | `000 00a faa fca d00 eb7 cc0 851 bbb 00f 080 8ff f00 f0f ff0 fff` |

どれも entry 0 が黒、entry 15 が白。当てて描くと

* タイトルは木目の楕円の銘板にクリーム色の地。花王の三日月、黄色の「倉庫番」、
  桃色の小箱、多色の「Select 30」、`SINCE 1982`、`(C) THINKING RABBIT INC.`
* エンディングはラビ君（緑の帽子・黄色のシャツ・青のオーバーオール）が
  「やったーっ!!」と両手を挙げ、隣に木箱
* タイルは煉瓦の壁・水色のゴール印・点・花王の木箱・ラビ君の歩行 4 方向

で、実物と一致する。

### FONT.CG — 確定

**76 レコード × 42 バイトの固定長。**

```
+0x00  06 00 08 00     全レコード同じ
+0x04  36 バイト       4 バイトずつ 9 組 = 4 プレーンをバイト単位で交互
+0x28  fe 23           全レコード同じ
```

4 バイト組の 4 バイトが同じ値なのは、文字が単色（4 プレーン全部同じ）
だから。描くと A〜Z と 0〜9 が 2 色ぶん並ぶ = 38 字 × 2 = 76。
**この「4 プレーンをバイト単位で交互」が絵の格納法**で、
`06 00 08 00` は幅 6・高さ 8 らしい。
