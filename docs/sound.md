# 音 — MMD2 ドライバと .BGM / .VOI

`disk/MMD2.SYS`（4655 バイト、DOS のキャラクタデバイス、名前 `MMD200OR`）を
逆アセンブルして読んだもの。番地は全部このファイルの中のオフセット。

```
python tools/mmdis.py disk/MMD2.SYS map 0x78 0x264
python tools/mmdis.py disk/MMD2.SYS fn 0x565 0x78 0x264
python tools/mmdis.py disk/MMD2.SYS ports 0x78 0x264
```

Ghidra は生バイナリだと入口が無くて 0 命令になるので、`tools/mmdis.py`
（capstone の流れ追い）を書いた。起点はデバイスヘッダの strategy 0x38 と
interrupt 0x41、それに interrupt が `cs:[bx+0x12]` で飛ぶコマンド表。

## ドライバの入口

デバイスヘッダのコマンド表（CS:0x12、13 個）は
`0f84 0062 0062 ...` で、**コマンド 0（init）が 0x0f84**、残りは
「何もせず完了」の 0x0062。

init は CONFIG.SYS の引数（`device = \mmd2.sys 3072 2048`）を読み、
OPN のポートを決め、`INT 21h AH=25h` で**ベクタを 5 本**取る:

| ベクタ | ハンドラ | 役 |
|---|---|---|
| `[0xc8d]` = **0xd2** | **0x0078** | API。ゲームが叩く口 |
| `[0xc96]`（下記の表から） | **0x0264** | OPN タイマ割り込み = 演奏 |
| 0x0f / 0x17 | 0x02c1 | 空の iret |
| 0x0a | 0x02c2 | 空の iret |

タイマのベクタは OPN のレジスタ 0x0e を読んで上位 2 ビットで
`0xc8e` の表 `0b 15 12 14 08 20 04 10` から選ぶ（ボードの種類ごと）。

OPN のポートは `[0xc7c]` / `[0xc7e]` に入る。init はまず **0x188 / 0x18a**
を試し、駄目なら旧ボードの **0x88 / 0x8a**。書き込みは

```
0x0347(al)   アドレスポートへ（ビット 7 が下りるまで待つ）
0x0356(al)   データポートへ
0x0369(al)   アドレスを書いてデータを読む
```

## API — INT 0xD2

`0x0078` が `ah` を見て `[bx + 0xc9c]` の表（22 個）へ `call`。

| AH | ハンドラ | 役 |
|---|---|---|
| 0x00 | 0x00bb | 初期化・停止 |
| 0x01 | 0x00f1 | 演奏開始。`0x374` で初期化して `0x411` で曲を開く |
| 0x03 | 0x0110 | 停止 |
| 0x06 | 0x012c | フェードアウト（AL = 速さ） |
| 0x08 | 0x0148 | 演奏中か |
| 0x10 | 0x0155 | 曲データを `CS:0x1384` へ CX バイト複写（上限 `[0xc82]`） |
| 0x11 | 0x0172 | 音色データを `CS:0x0f84` へ CX バイト複写（**上限 0x400**） |
| 0x0c/0x0d/0x0f/0x14/0x15 | | その他 |

`SBPVOICE.VOI` はちょうど **1024 = 0x400 バイト**で、音色バッファに丸ごと
入る。置き場が 0x0f84 = init の入口と同じなのは、init が常駐後に捨てられる
領域を音色バッファに使い回しているから。

## 曲の構造

`0x0411` が `0x0460` を **2 回**呼ぶ。1 回で 3 本ぶん、合計 **6 本** =
YM2203 の FM3 + SSG3。呼ぶ順に **前半 3 本が FM、後半 3 本が SSG**
（タイマ ISR は `0x0565` を 0,1,2 と 0x80,0x81,0x82 で呼び、`si` は
`0xdc0` から `0x2b` 刻み）。

`0x0460` はトラックを順に走査して頭の位置を覚える:

```
[bx]   = 1        使用中
[bx+1] = 曲中の位置（ワード）
bx    += 0x2b     トラック状態は 43 バイト
走査: al = *p++
      al == 0    ならこのトラックの終わり
      al <  0xfc なら引数無し
      al == 0xfc なら引数 2 バイト
      それ以外   なら引数 1 バイト
```

だから **`.BGM` は 0x00 で終わるトラックが 6 本並んだもの**。
`SBPBGM3.BGM`（453 バイト）は `72 00` が 6 回出て、ちょうど 6 本。

## タイマ割り込み — 0x0264

```
0x0264  SS:SP を自前のスタックへ、レジスタ退避
0x0288  [0xcc8] がフェード計数。0 なら 0x048d を呼ぶ
0x029d  call 0x048d                毎回の仕事
0x02a0  OPN レジスタ 0x27 = 0x2a    タイマ A/B の確認と再開
0x02aa  call 0x02f1                PIC へ EOI
0x02c0  iret
```

`0x048d` が

```
[0xde6] += 0x40                      テンポの分数計数
si = 0xdc0
0x0565(0) 0x0565(1) 0x0565(2)        FM の 3 本
0x0565(0x80) 0x0565(0x81) 0x0565(0x82)   SSG の 3 本
[0xf7e] が 0 なら [0xcc8] += 8       全部止まったら曲を閉じる
```

## フェードアウト — 確定

**画面が変わるときに曲が消えるのはこれ。** ゲームは曲を止める手段を
これしか持っていない。

### ゲーム側 — `FUN_24d7_00a8`

曲を鳴らす口は 2 つある。

```
FUN_24d7_001d(n)      n = 0..5、表引きで sbpbgmN.bgm を渡す
FUN_24d7_00a8(いま, 名前)
    ファイルを開いて読む
    いま != 0 → 音色として AH=0x11 で送るだけ（sbpvoice.voi）
    いま == 0 → ここが曲の道
        FUN_24d7_0051(1)          → AH=0x06、AL = [0x04a6] = 8。フェード開始
        while (AH=0x08) ;         → ドライバが「止まった」と言うまで空回り
        AH=0x10 で曲を送り AH=0x01 で鳴らす
```

`FUN_24d7_001d` は 6 面とも `いま = 0` で呼ぶ。つまり
**曲の切り替えは必ずフェード → 停止待ち → 次の曲**で、同じ曲をもう一度
頼んでも同じ道を通る（1edb:1554 の再開がそれ）。

呼ぶ場所は 6 つ。どれも `[0x128d]`（音のオン・オフ）が立っているときだけ:

| 番地 | 曲 | いつ |
|---|---|---|
| 1edb:03b3 | 0 | タイトルのあと、面選択の前 |
| 1edb:1053 | 2 | 面に入る。**盤面を描く前** |
| 1edb:11c7 | 4 | クリア。**「よくやった」の絵を出す前** |
| 1edb:1491 | 3 | 手数切れ |
| 1edb:1554 | 2 | 絵のあと、同じ面をもう一度 |
| 1edb:406c | 1 | エンディング |

**待っているあいだゲームは止まる。** 空回りの中では絵も描かないしキーも
読まないので、前の画面が出たまま約 3 秒過ぎて、それから次の画面になる。

### ドライバ側 — AH=0x06 と `0x08a8`

```
0x012c  [0x0f80] == 0 なら 0x0110（ただの停止）
        [0x0cc8] != 0 なら何もしない（もう終わりかけ）
        0x0420: [0x0f6e] = AL | 0x80        速さ＋走っている印
```

`[0x0f6f + ch*2]` が (数え, 減衰) の組。FM 3 本、SSG 3 本で 6 組。
音量を書く `0x08a8` が**呼ばれるたびに**数えを 1 進め、速さに届いたら
減衰を 1 段動かす:

* FM は +4、上限 0x7f（`0x0921`）。書く値は `音量 + 減衰`、0x7f 止め
* SSG は +1、上限 15（`0x08d8`）。書く値は `音量 - 減衰`、0 止め

`0x08a8` はふだん音量やキーオンのときにしか呼ばれないので、フェード中は
`0x05d3` が**毎ティック全トラックぶん呼ぶ**。だから音符の多いチャンネルは
そのぶん少し速く消える。

終わりの判定は `0x048d` の頭。`[0x0f7d] = 0x40` より **FM 3 本の減衰が
全部大きく**なったら `0x0374` で全部消して `0x041b` で曲を開き直し、
`[0x0cc8] += 8`。以後の割り込みは `0x0288` で `[0x0cc8] += 8` するだけに
なり、バイトが 0 に回った時点で `[0x0f80] = 0` ——ここでゲームの空回りが
明ける。

速さ 8 なら 1 段 9 ティック、17 段で 612 割り込み、締めの 32 を足して
**約 2.9 秒**。移植で測ると 616 割り込み = 2.84 秒
（`tmp/sound_check.exe` が出す）。

### 移植では

`mmd2_fade()` が AH=0x06、`fade_level()` が `0x08a8` の前半、`mmd2_tick()`
の頭が `0x0288` と `0x048d` の判定。ゲーム側は `app_music()` が
`FUN_24d7_00a8` で、待っているあいだは `app_tick` が何もせず
`app_busy()` が 1 を返す。

待ちを解くのはドライバが止まったことだが、この移植のドライバの時計は
**音声コールバック**なので、ブラウザがまだ音を鳴らしていないと永遠に
止まらない。`BGM_WAIT_TICKS = 200` フレームで諦めるようにしてある。
原作には無い安全弁で、音が鳴っている限り先にドライバが終わる。

## トラック状態（43 バイト）

| 位置 | 中身 |
|---|---|
| +0x00 | 残り長さ。毎ティック `dec`、0 で次のコードを読む |
| +0x01 | 曲中の位置（ワード） |
| +0x03 | いまの音長 |
| +0x04 | いまの音程（FM は F-number、SSG は周期） |
| +0x05 | 0x80 で SSG のノイズ |
| +0x06 | オクターブ 0..7 |
| +0x07 | 音量 0..15 |
| +0x08 | デチューン |
| +0x09, +0x0a | ゲート長と旗（bit 0x40 = タイ、下位 3 bit = q） |
| +0x0b..+0x0f | ソフト LFO（周期・深さ・限界） |
| +0x15 | 音色番号 |
| +0x1c..+0x1e | ループの回数と戻り先 |

## MML — 0x0565 と 0x0618

コードの読み方は `0x0618`:

```
al = *p++
al == 0 なら 0x87f（トラック終了）
al--                        コードは 1 起点
bx = 0xcca                  範囲表
  al < [bx] なら [bx+1] を call（al = 範囲内の位置）
  でなければ al -= [bx]; bx += 3; 繰り返す
戻ったら次のコードへ
```

範囲表 `0xcca` は「(個数, ハンドラ)」の三つ組が 19 個で、**1..255 を
余さず覆う**。

| コード | 引数 | 意味 |
|---|---|---|
| 0 | | トラックの終わり |
| 1..36 | | **音**。`0xd14` の 36 個 × 4 バイト表を引く |
| 37 | | 休符（`[si] = [si+3]`） |
| 38, 39 | | オクターブ −1 / +1 |
| 40..47 | | オクターブ = コード − 40 |
| 48, 49 | | 音量 −1 / +1 |
| 50..65 | | 音量 = コード − 50（0..15） |
| 66..97 | | SSG のノイズ周期 = コード − 66（32 段）。`[si+5] = 0x80` |
| 98..113 | | **ループ開始**。回数 = コード − 98、**0 は無限** |
| 114 | | **ループ終了** |
| 115..130 | | `[0xdb4]` の表から 3 バイト取る |
| 131..146 | | `[0xdb6]` の表から 3 バイト取る |
| 147..150 | | 音長を相対で足し引き |
| 151..241 | | **音長 = コード − 151**（0..90 ティック） |
| 242, 243 | | タイを切る / つなぐ（`[si+0x0a]` の bit 0x40） |
| 244..251 | | ゲート比 q = コード − 244（`[si+0x0a]` の下位 3 bit） |
| 252 | 2 | **チップのレジスタに直接書く**。`0x0821` が 1 つめを ch、2 つめを al にして `0x042a`（唯一の書き込みルーチン）へ落ちる |
| 253 | 1 | **変調プリセット**。`[0xdb8]`（`.VOI+0x60`）の 4 バイトを `[si+0x15] [si+0x16] [si+0x18] [si+0x19]` へ。`[si+0x15]` の下位 2 ビットが `0x0d0c` の 4 種のソフト LFO を選ぶ |
| 254 | 1 | **音長 = 引数**（90 を超える長さ用） |
| 255 | 1 | **レベル = 引数**（`0x085a` が `[si+8]` に入れる）|

252 を「ジャンプ」と読んでいたのは、最初にループのコード（98 / 114）を
見落としていたから。**6 曲のどれも 252・253・255 を使っていない**（251 より
上で出てくるのは 254 だけ）ので実害は出ていなかった。

引数の読み出しは `0x0a65`。252 が 2 バイト、253/254/255 が 1 バイトで、
トラック走査の「0xfc は 2、それ以上は 1」と一致する。

## 音程表 — 0xd14

36 個 × 4 バイト。`+0..1` が FM の F-number、`+2..3` が SSG の周期
（オクターブぶん右シフトして丸める）。

```
idx  FM      SSG      idx  FM      SSG      idx  FM      SSG
  0  0x0265  7664       12  0x0306  6112      24  0x03d0  4832
  1  0x026a  7639       13  0x030b  6052      25  0x03d5  4812
  2  0x026f  7583       14  0x0311  6031      26  0x03da  4767
  3  0x028a  7216       15  0x0333  5728      27  0x040a  4576
 ...                    ...                   ...
 11  0x02e5  6367       23  0x03a4  5071      35  0x0496  3999
```

比を見ると **3 個で 1 半音**、36 個で 1 オクターブ。組の中の 2 段は
5〜13 セントの微調整。これは飾りではなく**実際にそう使われている**:
`SBPBGM3.BGM` の 1 本目が `0c 12 09 1b 18`、2 本目が `0b 11 08 1a 17` と
**全部 1 つ下**で、同じ旋律を僅かにずらして 2 声で厚くしている。

## 実際の読み

`SBPBGM3.BGM` の 5 本目（SSG）の頭:

```
62 2b a3 3d 17 3c 17 3b 17 17 27 3d 02 3c 02 3b 02 02 ...

62 = 98   範囲 7
2b = 43   オクターブ = 3
a3 = 163  音長 = 12 ティック
3d = 61   音量 = 11
17 = 23   音 23
3c = 60   音量 = 10
17        音 23
3b = 59   音量 = 9
17        音 23
17        音 23
27 = 39   オクターブ +1
```

音量を 11 → 10 → 9 と落としながら同じ音を刻む = SSG の音量レジスタで
減衰を作った打楽器。1 ティックは 96 分解能で、曲に出る音長 6 / 12 / 24 /
48 / 72 と `fe 60`（= 96）がそれぞれ 1/32・1/16・1/8・1/4・付点 1/4・
全音符に当たる。

## ループ — ここを取り違えていた

`0x0747`（範囲 7）は「LFO の押し込み」ではなく **ループの積み込み**だった:

```
si += 0x2a; di = si; si -= 3; cx = 12; std; rep movsb    12 バイトを 3 ずらす
[si+0x1c] = al          回数（範囲内の位置。0 は無限）
[si+0x1d] = 現在位置
```

`0x076a`（コード 114）が終わり:

```
al = [si+0x1c]
al == 0 なら常に [si+0x1d] へ戻る（無限ループ）
al-- して 0 でなければ戻る
0 になったら枠を捨てる（12 バイトを 3 戻す）
```

3 バイト × 4 段。**各トラックの先頭が `0x62` = 98 = 回数 0**、末尾が
`72 00` = **114（ループ終了）+ 終端**。つまり曲はここで無限に繰り返す。
最初はこの範囲を読み飛ばしていたので、曲が一度も繰り返さず走り抜けていた。

## テンポ — 推測をやめて確定した

`0x0202` が

```
レジスタ 0x26 = 0xf0     タイマ B の周期
レジスタ 0x27 = 0x3a     タイマ B を読み込んで割り込みを許可
```

を書く。YM2203 のタイマ B は `clock / (1152 × (256 − N))` なので

```
3993600 / (1152 × 16) = 216.67 Hz
```

割り込み 4 回で音楽ティック 1 つなので **54.17 ティック/秒**。全音符が
96 ティック（`fe 60`）なので 4 分音符が **135 BPM**。

最初は 600 Hz と推測していて、**2.8 倍速すぎた**。これが「音がめちゃくちゃ」の
主因だった。

## 音量とゲート

音量は `0xda4` の 16 段表で総レベルに直し、**キャリアのレジスタに直接書く**
（`0x0960` が表の値をそのまま書き込みに渡す）。声の持つ TL に足すのではない。
キャリアはアルゴリズムで決まり、`0x093b` が 0..3 なら `0x4c+ch` だけ、
4 は 2 本、5・6 は 3 本、7 は 4 本を書く。

音を切る位置は `0x080a`:

```
ah = [si+3]; al = 0      ax = 音長 × 256
ax >>= 3                 ax = 音長 × 32
bx = [si+0x0a] & 7       q
mul bx
[si+9] = ah              = 音長 × q / 8
```

`0x0584` が毎ティック「残り長さが `[si+9]` に一致したら音を切る」。
`[si+9]` が 0 のときは FM 側だけ切り、SSG は次の音まで持続する。

休符は `[si+0x0a]` に 0x40 を足してビット 7 が立ったら 7 を落とす =
**タイを打ち消す**。

## 曲と場面の対応 — Ghidra が 2 か所見落としていた

生バイナリを `callf 14d7:001d` で走査すると呼び出しは **6 か所**あり、
Ghidra の逆コンパイルは 4 か所しか拾っていなかった:

| 番地 | 曲 | 場面 |
|---|---|---|
| `1edb:03a7` | **0** | `FUN_1edb_03c9`（面選択）の直前 |
| `1edb:10ae` | **2** | 面に入るとき |
| `1edb:121b` | **4** | 下記 |
| `1edb:14e5` | **3** | `1edb:14bb` が `cmp [0x152b], [0x11db]`（歩数 対 制限）で `jae` を取った先 |
| `1edb:15af` | **2** | 待ってから `0x10cd` へ戻る = やり直し |
| `1edb:40c0` | **1** | エンディング（END1.CG と一緒） |

肝は `0x121b`。手前が

```
call FUN_1edb_3182 ; or ax, ax ; je 0x1210   ← 0x1210 が BGM 4
```

で、`FUN_1edb_3182` は**盤面の値 2 の数 = ゴールに乗っていない荷物**を
数える。つまり 0 になるのは面が解けたときだけで、**4 はクリア曲**。
プレイ中に流れ続けるのは入るときに鳴らした **2**。

最初は 4 をプレイ中の曲にしていたので、面の間ずっとクリアのファンファーレが
鳴っていた。

**5 はどこからも呼ばれない。** 6 つのファイル名はどれもちょうど 1 回しか
参照されず、全部この分岐表の中にある。

## まだ無いもの

* コード 253 の変調（ソフト LFO 4 種）。**6 曲のどれも 253 を使わない**ので
  鳴らせる曲が無い。書いても確かめようがないため入れていない
* 効果音（AH=0x0c / 0x0d）。**この game は使わない** —
  ラッパ `FUN_2502_0082` / `FUN_2502_0094` を呼ぶ far call が実行ファイルに
  1 つも無い（`python tools/exedis.py calls 2502:0082`）

範囲 9 / 10（コード 115..146）の適用と `0x08a8` のソフトエンベロープは
入った。後者はフェードアウトそのものだった（上の節）。
